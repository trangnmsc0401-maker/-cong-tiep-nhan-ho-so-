## Project context

This is a teaching repo for a 6-week course ("DuHoc24" — a study-abroad application portal). The current state (Week 1) is **UI only**: every page reads from hardcoded mock data in [lib/mock-data.ts](lib/mock-data.ts). There is no real API, database, or auth yet — don't add one unless asked, and don't "fix" the lack of persistence; it's intentional for this stage. See [README.md](README.md) for the full week-by-week plan (Gemini chatbot in week 2, Supabase + real forms in week 3, document extraction in week 4, Make.com automation in week 5, auth in week 6).

## Commands

```bash
npm install
npm run dev     # next dev, http://localhost:3000
npm run build
npm run start
npm run lint    # eslint
```

There is no test suite configured.

## Architecture

- **Next.js App Router** on a version newer than this model's training data (`next@16.3.0`) — per [AGENTS.md](AGENTS.md), read `node_modules/next/dist/docs/` (generated by `next dev`/`next build`) before relying on App Router conventions from memory; APIs like typed layout props (`LayoutProps<"/">` in [app/layout.tsx](app/layout.tsx)) may differ from older Next.js.
- **Routes**: `/` (landing: hero, quote form, chatbot widget, highlights, footer), `/portal` (student document upload/status UI), `/admin` (redirects to `/admin/requests`) with sub-routes `requests`, `schools`, `profiles`, `conversations` sharing [app/admin/layout.tsx](app/admin/layout.tsx) (sidebar + mobile nav from [components/admin/sidebar.tsx](components/admin/sidebar.tsx)).
- **Mock data layer**: [lib/mock-data.ts](lib/mock-data.ts) is the single source of truth for all domain types (`DocStatus`, `RequestStatus`, `ServicePackage`, `School`, `AdmissionRequest`, `StudentProfile`, `Conversation`, etc.) and their mock instances. Pages import directly from here instead of fetching; when wiring up real data in later weeks, this file is what gets replaced.
- **Status presentation**: [components/status-badge.tsx](components/status-badge.tsx) centralizes the tone/label/icon mapping for `DocStatus` and `RequestStatus` (`docStatusMeta`, `requestStatusMeta`) — add new statuses there rather than inlining colors in pages.
- **UI components**: [components/ui/](components/ui/) holds shadcn/ui primitives (style `base-nova`, built on `@base-ui/react`, see [components.json](components.json)) generated via the shadcn CLI — treat these as generated/vendored rather than hand-rolled, and prefer regenerating/extending via shadcn conventions over ad hoc edits. Styling uses Tailwind CSS v4 (no `tailwind.config`, CSS-based config in `app/globals.css`) with `cn()` from [lib/utils.ts](lib/utils.ts) (`clsx` + `tailwind-merge`) for class merging, and `class-variance-authority` for variants (see [components/ui/button.tsx](components/ui/button.tsx)).
- **Landing page blocks** under `components/landing/` originate from the `@tailark-oss/dusk-landing-2` block kit (registry configured in [components.json](components.json)), re-themed to light mode and localized content — expect shadcn/tailark conventions (data-slot attributes, cva variants) rather than fully custom markup.
- **Locale/content**: all UI copy is in Vietnamese; the root `<html lang="vi">` ([app/layout.tsx](app/layout.tsx)) uses the `Be_Vietnam_Pro` Google font for Latin + Vietnamese subsets. Keep new UI text in Vietnamese consistent with existing pages.
- **Env vars**: [.env.example](.env.example) lists variables for future weeks (Supabase URL/key, public site URL) — none are required for the current mock-data-only build.
